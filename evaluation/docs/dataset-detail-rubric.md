# Prior-work input detail filter v1

The target is NL self-containment, not FQL expressibility or agreement with an Ansible implementation. Freeze this rubric before collecting model labels.

1. Strip only a leading `name:` label and surrounding whitespace. Keep SHA-256 of the original input plus its source file, repository path and zero-based row index. Source data and complete NL/message manifests remain private.
2. Free exclusions, in order: missing/non-string/empty NL; unresolved Jinja delimiters in NL; debug/assert/include/import/set_fact/fact-gathering/meta/variable-loading style; no candidate concrete object after generic action/resource words are removed. Explicit paths, URLs, non-generic quoted values, names or non-generic object tokens qualify as candidates. This is a broad candidate screen, not the final detail judgment.
3. Style detection checks NL words and, when available, a top-level Ansible module name solely to exclude the explicitly requested debug/assert/include/set_fact-style task classes. The Ansible YAML is never sent to a model. No other YAML fields inform object/detail decisions or FQL generation.
4. Classify every unique surviving normalized NL with the committed `detail-filter-v1.txt`, DeepSeek V4 Flash, LOW effort, batches of up to 20 independent NL names and 4,096 maximum output tokens. Cache only exact normalized-NL duplicates, retaining every source row in the funnel. No Ansible output or repository metadata enters the classifier messages.
5. Keep only a completed, valid JSON label with keep=true and reason=concrete_self_contained. A package name to install or service name to start needs no invented version. Copy/move needs both endpoints; edits need path and requested change; downloads need URL and destination; permissions need path and mode/subjects; identity/config/key changes need named targets and values. Unresolved contextual conditions are insufficient. Classifier API/format failures are unresolved exclusions, separately counted, not ordinary detail rejections.
6. Do not screen by the FQL KB, compiler, model outputs, references or Ansible correctness. Record a separate conservative NL-only support hint (known package/service, likely primitive, needs KB entry, or unknown); it never changes keep/sample decisions and is not a semantic-validity label.
7. Select up to 300 kept rows uniformly without replacement with seed 20261112. Preserve duplicate NL rows if present; row identity, not text uniqueness, defines the sample. All six models use exactly the same sampled rows. Publish only IDs/hashes, labels, model outputs and aggregate counts; report ten kept and ten dropped excerpts for the user's requested sanity check without committing the source corpus.

Generation uses handbook-v3, four explicitly frozen demonstrations, one fresh call per sampled row/model, HIGH effort (Qwen XHIGH), 32,768 output tokens and no seed/temperature/top-p. Record the fixed-demo choice as a new dataset policy: the old matrix had four target-specific demos, not one global set. No target Ansible, gold FQL or classifier judgment enters generation.

Budget: $20 total for classifier and generation together; $8 Anthropic. Durable reservations, usage reconciliation and bounded transient retries (including 524) apply. Finish other providers when the Anthropic guard binds; record pending cells and API failures separately. Scoring counts nonempty grammar parsing, semantic acceptance and native symbolic interpretation independently. No reference matching, execution tests, output judge or correctness claims.
